# SigNoz implementation plan

> Execution: inline, as requested. Prepare code on `feat/signoz-observability`; do not deploy.

**Goal:** Environment-controlled frontend/backend telemetry for self-hosted SigNoz.
**Architecture:** Browser XHR/fetch traces propagate W3C context only to the configured API. Backend instrumentation starts before Express/MySQL load and exports batched traces, runtime metrics, and correlated Winston logs over OTLP/HTTP. Disabled by default. The collector, storage, UI, and alerts are operated separately.
**Stack:** OpenTelemetry JavaScript SDKs, Winston, existing React/Vite and Express/MySQL2.

## Constraints and review focus
- No browser ingestion secrets; frontend URL is browser-accessible and HTTPS with an HTTPS app.
- Exclude exporter traffic; never send headers, request bodies, SQL literals, URL queries, or reset tokens in telemetry.
- Existing startup, auth, CORS, and API responses continue to work with telemetry disabled or collector unavailable.
- Preserve worker shutdown semantics and batch flushing.
- Frontend dependencies approved through the user's explicit instrumentation pipeline response. Frontend AGENTS.md excludes unprompted test files; verify its build and runtime integration instead.
